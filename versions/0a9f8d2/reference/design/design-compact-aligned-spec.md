# Design Compact 对齐规范

本文件是 offline skill 的唯一非协议生成规范，映射自 CreateMyCard：

- 上游：`widget_service/cloud/data/protocol_profiles/design-compact-dsl/PROMPT.md`
- 分支：`dev`
- 对齐提交：`91e8be400099189756f3c9d7d0f6614387d40c02`
- 原文链接：<https://github.com/linfachen-lff/CreateMyCard/blob/dev/widget_service/cloud/data/protocol_profiles/design-compact-dsl/PROMPT.md>

对齐范围包括任务选择、信息与动作预算、固定骨架、几何、字体、颜色、图表、素材、动态状态和自检规则。上游的极简协议表示、TaskSpec 字段和 few-shot 示例不进入输出；它们必须映射为本项目的完整 Form DSL、DataModel 与 CardSpec。

固定骨架是关系和预算约束，不是固定文案、示例值、组件 JSON 或素材组合模板。卡片内容仍由当前 query、已声明能力、事件和素材自由生成。

信任优先级固定为：本规范和完整 Form 协议硬规则 → capability/event/asset 声明的合法上限与用户指定尺寸 → query 的内容目标、候选取舍和视觉偏好 → 示例。候选存在不代表必须使用；示例不授权额外事实、字段、路径、事件、素材或尺寸。

## 1. 任务收敛

每张卡必须满足：

- 只服务一个对象或一个主问题。
- 只有一个主显示组和一个视觉焦点。
- 只使用一个主色族，最多再使用一个真实状态/动作色。
- 最多三层信息层级。
- 每个可见组件有唯一职责，不放装饰填空，也不重复同一事实。

写 DSL 前，把候选数据、素材和事件分为：

- `mustKeep`：没有它就无法回答主问题；必须显示。
- `shouldKeep`：有助于判断，但空间不足可删。
- `drop`：重复、低价值、越界或会制造第二主问题；不进入卡片。

只选择最小充分字段：

- 2x2：一个主信息，最多两个支撑事实。
- 2x4：一个主结构，最多四类支撑信息。

只有用户明确给出的静态文案、称呼、地点或目标可以作为静态事实。不得凭常识补写电话号码、联系人、私人日程、精确位置、健康/设备/账户状态或其它用户事实。动态状态未返回时使用中性标题，或删除只在某状态成立的图标和结论。

样例值只用于首帧预览，不代表真实用户数据。凡是会在运行时变化且来自能力输出的可见值，都必须动态绑定，不能把样例或其同义改写写成静态文案。没有样例时使用同类型非敏感占位：string 为“示例”、integer/number 为 `0`、boolean 为 `false`、null 为 `null`；不得把占位表述为已读取的事实。纯静态/纯事件卡也要在 `/state` 初始化最小辅助值。

## 2. 事件决策

事件分三类：

- `explicit`：用户明确要求打开、查看、导航、拨打、启用、清理、播放等动作；必须保留并绑定已声明事件能力。
- `implicit`：安全、无副作用、进入同一对象详情的动作；可绑定 root，不额外制造按钮。
- `sideEffect`：会改变状态或产生外部影响；只有用户明确要求时才保留。候选事件中存在该能力不等于用户授权。

默认最多一个显式动作。第二个动作只有在用户明确需要且所选骨架允许时才能出现。只有 `wide-four-action-hub` 允许 3–4 个同一对象、同等重要且全部被明确要求的动作。

- 同一动作不能同时绑定 root 和按钮。
- 无真实事件时不保留按钮外观。
- 静态状态结论不能与运行时数据矛盾，也不能硬编码会变化的状态。

## 3. 画布与通用预算

### 尺寸

| 尺寸 | 画布 | root padding | 内部安全区 |
| --- | --- | --- | --- |
| `2x2` | `160×160vp` | `12vp` | `136×136vp` |
| `2x4` | `320×160vp` | `12vp` | `296×136vp` |

- 用户指定尺寸后不得自动升降尺寸；未指定时默认 2x2。
- root `width/height: "matchParent"`、`borderRadius: 18`、`clip: true`，并显式提供背景。
- root 的圆角/裁切不能掩盖内部布局失败。

### 间距与圆角

- 间距只用 `2/4/6/8/10/12/14/16vp`，优先 `4/8/12/16`。
- 组间间距不得小于组内间距。
- 内部小板圆角 `8–12vp`；主要支撑板 `12–16vp`；胶囊圆角为高度一半。
- 点击目标最小 `24×24vp`。

### 容量

- 2x2：最多 3 个主区域、1 个显式动作、1 个内部内容背板。
- 2x4：最多 4 个主区域；默认最多 2 个动作；最多 1 个主背板 + 1 个弱支撑背板。
- 禁止 dashboard、多表面页面、任意按钮网格或卡片套卡片；仅 `wide-four-action-hub` 允许受控的四动作网格。
- 一个表面只用一种主要层级信号：背景填充、边框、阴影三者至多强化一种。

2x2 任一候选无法通过文字或布局压力时，强制回退，不继续横向压缩：

- 有显式动作：`header/context 20 + hero 56–64（内部最多一条支撑）+ full-width action 36`，直接组与间距总和不超过136。
- 无显式动作：`header/context 20 + hero 56–64 + full-width support 16–28`，直接组与间距总和不超过136。
- 回退骨架外不得再加窄侧边文字动作、第二条长格式化值或独立弱 footer。

### 布局计算

关键内部容器、Image、Progress、Button 必须使用数值宽高。每个 Row/Column 同时检查主轴和交叉轴：子项宽高、margin、容器 padding、`itemMargin` 全部计入。使用 `spaceBetween/spaceAround/spaceEvenly` 时不得再使用 `itemMargin`，且子项尺寸必须稳定。

Text 与 Button 同行时，至少保留 `4vp` 未用水平余量。所有安全公式都应把 `4vp` 余量计入，不用恰好贴满。

- 窄于父容器的主焦点或动作必须由父级 `alignItems`，或全宽 Row/Stack，显式决定交叉轴位置；组件自己的内部对齐不能证明它相对父容器已居中。
- 2x2 的文字主动作优先使用底部全宽 Button/Row，不把 Image+Text 塞进小于 `56vp` 的侧栏；底部动作距安全区底边不超过 `16vp`。
- Stack 不得遮挡。允许主焦点周围有较大留白，但留白不能像缺失组件、空槽或未加载区。
- 同一信息组共享左边界、中心线或基线；除真实对比外，相邻主信息不使用近似但不相等的宽高/边距。
- 组内距通常 `2–6vp`，同级组间距通常 `8–12vp`，主区域间通常 `12–16vp`，不无理由交替多个相近间距。

## 4. 2x2 固定骨架

### `compact-metric-action`

适用：指标、状态、时间、内存、倒计时、可量化进度。

- `header 20 + gap + hero 56–64 + optional gap + action 36 <= 136`
- 一个主值，最多一个支撑事实。
- 仅在有可靠范围/总量时使用一个进度图。
- 动作必须真实需要；无动作时把空间交给主值和支撑。
- 禁止两个主值、两个动作、长说明和无比例语义的 Progress。

### `compact-event-action`

适用：下一日程、提醒、电话、导航、入口、设置。

- `header 20 + gap + event 56–64 + optional gap + action 36 <= 136`
- 事件标题 + 时间/状态 + 最多一个弱支撑。
- 一个显式动作，或 root 上的同对象隐式详情动作。
- 禁止两条独立事项、多按钮，以及长地点与长说明同时出现。

### `compact-date-next`

适用：日期、倒计时、下一安排。

- 日期/数字区 `48–56vp`。
- 下一项区 `56–72vp`。
- 只有总高度闭合时才加 `20vp` 短标题。
- 地点只属于 `shouldKeep`；不放显式文字 CTA，不引入第二业务域，也不展示多条事项。

### `compact-dual-fact`

适用：同一对象的两个短、可比较事实。

- 有标题：`header 20 + gap 8 + factsRow 108`。
- 两事实面板各约 `62vp` 宽，中间 gap `8vp`，保留 `4vp` 余量。
- 无标题时可做两个更高的等权面板。
- 两项必须完全同构；禁止四宫格、两个对象、左右结构不一致和长文本。

### `compact-dual-item-summary`

适用：恰好两条日程、闹钟、状态或记录。

- `header 20 + gap 8 + list 108`。
- 两项各约 `52vp` 高，项间 `4vp`。
- 可用 root 隐式进入详情，不加 CTA；禁止三项及以上、逐项按钮、长地点、图片列表和高对比独立卡面。

## 5. 2x4 固定骨架

### `wide-hero-context`

- 左右区 `104 + 8 + 180`，或镜像；保留 `4vp` 余量。
- 一个 hero + 一个 context，最多一个动作；禁止两侧同时高饱和、两个主焦点或两个无关对象。

### `wide-timeseries-strip`

- `header 20 + gap + series 64–108 + optional action 36`。
- 3 项建议每项 `88vp`；4 项不超过 `67vp`；5 项不超过 `52vp`；间隔 `8vp` 并保留 `4vp`。
- 只有每项为短字段且可确定展示数量时才使用4–5项，否则最多3项。禁止每项背板/动作、不同层级混排、长标题或6项以上。

### `wide-agenda-stack`

- 无 CTA：`header 20 + gap 8 + list 108`，展示 2–3 项。
- 有 CTA：`header 20 + gap 8 + list 64 + gap 8 + action 36`，最多 2 项。
- 单项最多标题、时间和一个弱字段；禁止完整月历、长滚动列表、三个不同动作和逐项高对比卡面。

### `wide-metric-detail-action`

- `104 + 8 + 180`，保留 `4vp`。
- 一个主指标，最多三个统一样式支撑事实；默认最多一个动作。禁止缺少主指标、超过三项支撑、多个图表竞争和长标签。

### `wide-dual-domain`

- `142 + 8 + 142`，保留 `4vp`。
- 两个域必须共同回答一个问题，每区一个短主值和最多两条支撑，共享标题/背景/动作；最多一个整体动作。禁止拼接无关迷你卡、两侧各有CTA或两个高饱和场景面。

### `wide-four-action-hub`

- 仅用于 3–4 个被明确要求的同对象、同权动作。
- `header 20 + gap 12 + actionGrid 104`。
- 两行各 `48vp`，行 gap `8vp`；每项 `142vp`，列 gap `8vp`，保留 `4vp`。
- 每个动作必须有一一对应的已声明事件候选、2–4字短标签和可见图标或明确文字。禁止用它展示数据、混入不同对象、混合主次悬殊动作、候选不足时伪造按钮或超过四项。

骨架共同约束：

- 2x2 主显示组通常占安全内容区高度 `40%–55%`；2x4 主区域通常占安全内容区宽度 `40%–62%`。
- 主辅优先采用非对称比例；只有真实比较、同级时间序列、双事实或同权操作集合允许等宽等高。
- 主要文字、数值、图标和动作至少形成一条共同对齐线；辅助信息围绕主焦点聚合，不散落四角。
- 背景图或高饱和场景面只配简单骨架和极少背板；中性 root 最多用一个弱内容面建立层级。
- 骨架与色板独立选择；不能因为尺寸/示例相同就一律复用蓝白配色。

## 6. 字体与受保护文本

只允许 `10/12/14/16/18/20/32/40fp`，每张卡最多三档字号。旧的 30/38fp 映射为 32/40fp。

- 主值：`700–800`。
- 主标题：`600–700`。
- 支撑文字：`400–500`。
- 只保留一个最强字重焦点。

受保护文本包括：显式标题、状态、日期/时间、主指标、价格、数量、联系人、CTA，以及带 `%`、`℃`、负号、货币或单位的完整格式化值。受保护文本不能依赖 ellipsis 或 clip。

宽度压力估算：

- 中文字符：`1.0 × fontSize`
- 英文与数字：`0.65 × fontSize`
- `% / ℃ / ° / 货币符号`：`0.8 × fontSize`
- 空格与窄标点：`0.4 × fontSize`
- 其他符号：`0.6 × fontSize`
- 可用宽度至少为估算值的 `1.2×`

2x2 保守槽位：

- 40fp 格式化主值至少 `104vp`；负数、三位数或长单位至少 `128vp`。
- 32fp 短格式化主值至少 `88vp`；负数或三位数至少 `104vp`。
- 12fp 整数百分比至少 `40vp`；小数百分比至少 `56vp`。
- 10fp `HH:mm-HH:mm` 至少 `84vp`。

格式化标量除当前完整样例外，还要压力测试语义允许的较长合法值：百分比至少测试 `100%`；允许负温/负金额时必须包含负号。无法可靠推导边界时，至少保留上述 `20%` 水平余量。

若 schema 只提供完整格式化字符串，不得在 UI 中擅自拆分数字和单位。

## 7. 动作、图标、进度和图片

### 动作

- 默认文字 Button 或图形 Row 按钮：高 `36vp`、圆角 `18vp`、文字 `14fp/600`、内容 padding 至少 `8vp`。
- 图形按钮 icon `20vp`，与文字间隔 `8vp`；中文标签默认 2–4 个字。
- 独立 icon 动作：`30×30vp`，中心 icon `16–20vp`，并提供可访问标签。

### 图标

- header icon：`20vp`。
- 常规语义 icon：`16–24vp`。
- hero icon：2x2 为 `40–56vp`；2x4 为 `48–72vp`。
- 多来源卡片不能使用某一个 App icon 代表整张卡片。

### 进度

- 只有数值范围或总量可靠时才使用。
- 2x2 最多一个 ring 或线性进度。
- ring 直径 `56–72vp`，stroke 为直径的 `14%–15%`。
- 线性进度：1–2 行高 `8vp`，3 行高 `4vp`。

### 图片

- 显式写 `width/height/objectFit`。
- SVG 默认使用 `fillColor`，除非素材描述要求保留原色、多色、品牌或透明效果；PNG 永不使用 `fillColor`。
- `fillColor` 必须根据直接背景与当前颜色角色选择。
- 只选完成任务所需的最少素材。2x2 通常一个主素材，并可按需要增加 1–2 个更小的状态/对象/动作素材；2x4 可按分区、序列或列表使用多个小型辅助素材。重复项中的同义图标不按实例机械计数，但每个实例都必须有区分价值并通过预算。
- 只有素材描述明确为背景/壁纸时才能当背景使用。
- 背景素材单独承担 canvas 职责，不占主素材名额，但使用后要降低前景素材尺寸、数量或对比度。

## 8. 表面策略与颜色

先确定一种表面策略：

1. 默认使用语义浅色板。
2. 可靠单应用/单对象可用约 10% 的弱主题色 + 白色。
3. 只有天气、睡眠、运动、夜间、音乐等低密度特殊场景使用渐变。
4. 只有夜间、睡眠、音乐、专注使用暗色舞台。
5. 只有精确匹配且安静的背景素材才使用背景图。
6. 2x4 分栏最多一侧高识别，另一侧保持弱表面。

从同一色族整组选择 canvas/surface/accent：

| 色族 | canvas（2-stop） | surface | accent |
| --- | --- | --- | --- |
| neutral | `#FFF5F7F9 → #FFFFFFFF` | `#FFFFFFFF` / `#FFF1F3F5` | 语义强调色或深灰 |
| warm coral | `#FFFFE9DE → #FFFFFCF8` | `#FFFFF5EF` | `#FFE56A3A` |
| sky blue | `#FFDCEEFF → #FFF4FAFF` | `#FFEAF4FF` | `#FF1769E0` |
| mint | `#FFE2F6EE → #FFF8FCFA` | `#FFE1F4ED` | `#FF0F8F78` |
| purple | `#FFF2E8FF → #FFFCF9FF` | `#FFF5EEFF` | `#FF8A4DCC` |
| orange | `#FFFFEDD6 → #FFFFFAF2` | `#FFFFF3E5` | `#FFED6F21` |

特殊同族高识别版本：

- 晴空蓝：`#FF0A59F7 → #FF46B1E3`
- 紫色舞台：`#FFAC49F5 → #FFC386F0`
- 正常状态绿：`#FF64BB5C`
- 橙色动作：`#FFF9A01E`

基础前景：

- 浅色主文字 `#E5000000`
- 浅色次文字 `#99000000`
- 浅色弱文字 `#66000000`
- 高饱和面主文字 `#FFFFFFFF`
- 高饱和面次文字 `#99FFFFFF`
- 暗色弱材料 `#19000000` / `#0C000000`
- 浅色弱材料 `#33FFFFFF` / `#19FFFFFF`
- 雨天补充色 `#FF46484D` / `#FF467794`

渐变规则：

- 恰好两个 stop，且来自同一色族。
- 不使用第三 stop、跨色族、彩虹、径向渐变、orb 或 bokeh。
- 渐变方向服务于当前骨架与视觉重心，不固定成同一个方向。

## 9. 完整协议映射

- 上游的 compact component arrays 必须转换为本项目的完整组件对象和 `styles`。
- 上游 TaskSpec 的数据/素材/事件候选，分别映射到 capability manifest、asset library 和 event capability；不输出 TaskSpec。
- root 全尺寸在完整 Form 中写 `width/height: "matchParent"`。
- 能力辅助状态放 `/view` 或 `/state`，不污染 `writeResultTo` 子树。
- 对新生成的短列表，优先用固定索引/固定组件以锁定几何；修复已有动态 List 时可以保留合法循环，但必须证明项数上限和预算。

## 10. 交付门禁

输出前逐项确认：

- 尺寸与用户要求、CardSpec 一致；root padding12、radius18、clip 与内部预算成立。
- 只回答一个主问题，所有字段都属于 mustKeep/shouldKeep，每个组件职责唯一。
- 骨架可明确命名，组件数量和动作数量未超预算。
- 所有动态值有能力来源并绑定；示例值未伪装成真实数据。
- 事件分类正确；副作用动作有用户明确授权；无重复点击。
- 受保护文本通过 1.2× 压力测试，没有 ellipsis/clip。
- 字号、字重、间距、圆角、按钮、icon、ring/进度满足规范。
- 颜色属于一个受控色族，最多一个额外状态/动作色；渐变恰好两个同族 stop。
- 素材语义匹配、数量最少、路径存在、SVG/PNG 染色规则正确。
- 三行 JSONL、组件引用、DataModel、绑定、事件和 CardSpec 完整闭环。
